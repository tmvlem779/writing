# 결정 기록

## ADR-001: 학교 초대형 이메일 인증

- 상태: 채택
- 결정: 교사가 학생 이메일을 초대하고 학생이 링크에서 비밀번호를 설정한다. 공개 회원가입은 제공하지 않는다.
- 이유: 특정 학교 수업 범위를 유지하고 계정 오남용을 줄인다.
- 추후: 학교가 Google Workspace SSO를 요구하면 별도 ADR로 변경한다.

## ADR-002: 서버 소유 AI 호출과 데이터 저장

- 상태: 채택
- 결정: OpenAI 호출, 안전 검사, 비용 검사, 학습 기록 저장은 Next.js 서버에서 수행한다.
- 이유: 비밀키를 보호하고 운영 우회를 막는다.

## ADR-003: 저비용 기본 모델

- 상태: 채택
- 결정: 기본 모델은 `gpt-5-nano`, 앱 내부 월 한도는 미화 6달러, 학생별 하루 40턴·세션별 30턴이다.
- 이유: 월 10,000원 목표에 환율 변동과 운영 여유를 두면서 Responses API 구조화 출력과 짧은 단계적 피드백을 지원한다.

## ADR-004: Instagram 실제 자료 연동 경계

- 상태: 제안 — 학교 개인정보·미성년자 보호 검토와 계정 선택 전에는 구현하지 않음
- 제안: 학생 개인 계정을 각각 연결하지 않는다. 교사가 관리하고 게시물 사용을 승인한 학급용 Instagram 프로페셔널 계정 하나를 공식 Instagram API로 읽는 방식을 우선한다.
- 최소 수집: 수업에 선택된 게시물의 본문과 게시물 식별자만 서버에서 가져오며, 학생 사용자명·프로필 사진·댓글·좋아요·위치·팔로워 정보는 저장하거나 학생 화면에 노출하지 않는다.
- 보안: OAuth 토큰은 서버에서 암호화해 보관하고 브라우저·로그·Git에 넣지 않는다. 연결 해제와 토큰 삭제 절차를 제공한다.
- 이유: 공식 API는 프로페셔널 계정을 중심으로 제공되며, 학생 개인 SNS의 연결은 수업 목적에 비해 개인정보와 동의 부담이 크다.

# 2026-10-01 · 저비용 모델과 응답 대기 피드백

- 문득문득의 짧은 구조화 질문 생성에는 비용 민감·대량 처리용 `gpt-5.6-luna`를 기본으로 사용한다.
- 지연 중 중복 제출을 막는 것에 더해, 버튼 안과 작업 영역에 `문·득·문·득` 로딩 표시를 함께 제공한다.
- 애니메이션은 `prefers-reduced-motion` 환경에서 정지하며 텍스트 상태 안내를 유지한다.
- 월 $6 제한은 실제 호출 모델별 입력·출력 단가로 계산하고, 등록되지 않은 모델은 비용을 과소 계산하지 않도록 보수적인 상한 단가를 적용한다.

# 2026-10-01 · 전 구간 로딩 피드백

- 로그인 성공 뒤 인증 화면에서 학습 화면으로 이동할 때까지 전체 화면 `문·득·문·득` 로딩을 유지한다.
- App Router의 `loading.tsx` 경계를 루트와 학생 학습 영역에 두어 서버 인증·데이터 조회와 학습 탭 이동에도 즉시 같은 피드백을 제공한다.
- 비밀번호 설정·초대·진단 저장·로그아웃 등 개별 비동기 동작도 버튼 또는 전체 화면 애니메이션으로 현재 상태를 알린다.
- 상태 안내는 `role=status`, `aria-live`, `aria-busy`를 사용하고 움직임 축소 설정에서는 애니메이션을 정지한다.
- 화면에는 설명 문구 없이 `문득문득` 네 글자만 표시하고, 구체적인 처리 상태는 보조기기용 접근성 이름으로만 제공한다.

# 2026-10-01 · 학교 아이디 기반 계정

- 특정 학교 수업에서 실제 학생 이메일을 수집하지 않도록 로그인 식별자를 학교 아이디로 전환한다.
- Supabase Auth 내부에서는 예약 도메인의 합성 주소를 사용하되, 학생·교사 화면에는 이메일을 노출하지 않는다.
- 교사가 아이디와 초기 비밀번호로 학생 계정을 생성하며 공개 회원가입은 계속 차단한다.
- 사용자 요청에 따라 비밀번호 정책을 8자 이상의 영문자+숫자로 조정한다. 영문 대문자와 소문자를 모두 허용하며 앱은 두 문자 종류와 허용 문자 범위를 직접 검증한다.
- 아이디·비밀번호 오류는 동일한 메시지로 처리하고, 서비스 역할 키는 서버 전용으로 유지한다.

# 2026-10-01 · 문득문득 ver.1 보존과 ver.2 시작

- Production 커밋 `e8ffd58`을 GitHub `ver1` 브랜치와 `v1.0.0` 태그에 함께 보존한다.
- ver.2에서는 학생 홈과 공통 학습 내비게이션의 `AI 진단평가` 진입 탭을 제거하되, 과거 진단 기록과 복구 가능한 코드는 삭제하지 않는다.
- 스스로 유형 학습에 `그림·상황 문장 만들기`를 추가한다. 학생이 그림을 관찰해 첫 문장을 만든 뒤 AI가 한 번에 하나의 질문으로 확장·수정을 돕는다.
- 그림은 외부 학생 데이터나 생성형 이미지에 의존하지 않는 자체 SVG 장면으로 제공하고 대체 설명을 포함한다.
- ver.2가 적합하지 않으면 `v1.0.0` 태그의 코드를 기준으로 복구하며 학생 데이터베이스는 되돌리거나 삭제하지 않는다.

# 2026-10-06 · 교사 학생별 학습 모니터

- 학생 계정 생성 시 이름과 학교 아이디를 분리하여 기록하고 교사 화면에는 담당 학급 범위의 최소 계정 정보만 표시한다.
- 학습 영역 시작 이벤트를 기존 학생별 RLS가 적용된 `learning_events`에 기록하여 오늘의 챌린지와 스스로 유형학습을 구분한다.
- 교사 화면은 15초마다 서버 데이터를 다시 읽고 오늘의 챌린지·스스로 유형학습·오답노트를 학생별 탭으로 제공한다.
- 정체 진단은 생성형 추측이 아니라 반복 오답, 독립 성공 비율, 비계 수준의 관찰 가능한 근거만 사용하며 교사의 판단을 대체하지 않는다.

# 2026-10-07 · 그림 없는 상황 문장 만들기

- 스스로 유형 학습의 문장 만들기에서는 자체 SVG 삽화를 모두 제거하고 학교생활 상황을 글로 제시한다.

# 2026-10-07 · 30일 문법 루틴과 오류 문장 복습

- 7일 로드맵을 지난 14일·오늘·앞으로 15일로 구성한 30일 로드맵으로 확장한다.
- 지난 날짜 활동은 다시 열어 학습할 수 있지만 완료 이벤트와 연속 학습에는 포함하지 않는다.
- 날짜별 노드와 안내 글은 위치와 관계없이 같은 간격을 유지한다.
- 다섯 번째 유형으로 `틀린 문장 고치기`를 추가하고, 오류 표시·수정·이유 설명을 모두 마친 뒤 완료한다.
- 그림을 없애면서 정보가 부족해지지 않도록 각 상황에 등장인물·행동·관계를 구체적으로 포함한다.
- 학생은 상황을 먼저 읽고 조건에 맞는 문장을 직접 만들며, 활용 어휘는 초기 비계로 유지한다.
- AI는 그림 관찰을 요구하지 않고 제시된 상황과 학생 문장을 바탕으로 한 번에 한 요소만 질문한다.

# 2026-10-07 · 모바일·태블릿 별도 조판

- 모바일은 상단 학습 탭을 가로 스크롤 목록으로 바꾸고 30일 로드맵을 한 줄 세로 흐름으로 표시한다.
- 태블릿은 모바일 규칙을 확대해 재사용하지 않고 두 열 대시보드, 지그재그 로드맵, 축약된 교사 현황 그리드를 별도로 사용한다.
- 한국어 제목·질문·버튼은 `word-break: keep-all`과 `overflow-wrap: break-word`를 적용하여 어절을 보존하고, 모바일·태블릿·PC 구간별 행폭에 맞춰 제목의 균형과 본문의 줄 흐름을 각각 조정한다.
- 학습 내용과 비계 순서는 바꾸지 않으며, 좁은 화면에서도 학생이 질문과 자기 답을 같은 맥락에서 읽을 수 있도록 조판만 조정한다.

# 2026-10-07 · 챕터 메뉴 스크롤 여백 제거

- 오늘의 챌린지 상단 학습 영역 메뉴는 유지하되, 챕터 전환 메뉴는 화면 상단에 중첩 고정하지 않는다.
- 챕터 전환 메뉴가 학습 내용과 함께 자연스럽게 스크롤되도록 하여 본문 위에 밝은 빈 영역이 남지 않게 한다.

# 2026-10-08 · 로그인 우선 첫 화면과 압축형 차시 표지

- 서비스 루트(`/`)는 책장 전환형 소개 화면을 거치지 않고 `/login`으로 바로 이동한다.
- 오늘의 챌린지 차시 표지는 데스크톱 260px을 기준으로 높이·제목·장식을 함께 축소하여 학습 내용이 더 빨리 보이게 한다.
- 1~6차시 표지 중앙의 장식 대표어는 모두 표시하지 않되, 차시 제목과 핵심 질문 등 실제 학습 내용은 유지한다.

# 2026-10-08 · 간결하고 밝은 로그인 화면

- 로그인 화면의 공통 메뉴, 보조 설명, 개인정보 링크, 장식 문자와 기록 표식을 제거해 브랜드와 계정 입력에만 집중한다.
- 첫 화면의 큰 제목은 `문득문득`으로 통일한다.
- 어두운 녹색·먹색 배경 대신 밝은 하늘색·연보라·분홍색과 따뜻한 흰색을 사용하며 입력 대비와 포커스 표시는 유지한다.

# 2026-10-08 · 학생별 통합 교사 대시보드

- 교사 대시보드는 왼쪽 세로 학생 목록과 오른쪽 선택 학생 상세 패널로 구성한다.
- 오늘의 챌린지는 6차시 개념 완료, 스스로 유형학습은 30일 완료, 오답노트는 다시 해결한 오답 비율을 진도율로 표시한다.
- 세 학습 영역은 별도 탭을 다시 누르지 않아도 한 화면에서 함께 비교할 수 있게 한다.
- 오답 문항·학생 답·재학습 단서와 AI 도움을 사용한 학습 영역·개념·비계 단계만 교사에게 제공하며, 담당 학급 RLS 범위를 유지한다.

# 2026-10-08 · 학급별 교사 대시보드

- `오늘 활동`, `도움 필요` 요약 카드는 제거하고 교사가 실제로 선택하는 학급과 학생 진도에 화면을 집중한다.
- 기존 `문법학급`은 첫 번째 학급 버튼으로 고정하고, 나머지 학급은 이름순으로 배치한다.
- 학급 버튼을 누르면 해당 학급의 학생 계정 목록과 학생별 세 영역 진도·오답·AI 도움 근거만 표시한다.
- 학급 등록은 서버에서 로그인과 교사 역할을 다시 확인한 뒤 학급과 교사 소속을 함께 생성하며, 중간 실패 시 불완전한 학급을 남기지 않는다.

# 2026-10-08 · 회차형 자기주도 학습과 교사 근거 분석

- 학생에게는 달력 날짜 대신 스스로 유형학습의 진행 순서인 `1 / 30`부터 `30 / 30`까지만 표시한다. 학습 가능 여부와 연속 학습 계산에는 기존 내부 날짜를 계속 사용한다.
- 교사 화면은 `학습 현황`과 `학습 분석`을 분리한다. 현황은 학생별 6차시·30회·오답노트 활동표와 클릭 상세를, 분석은 학생별 AI 힌트 사용 개념·횟수와 오답 유형·시도 횟수를 제공한다.
- 다음 활동 제안은 관찰된 최다 오답 유형과 최다 힌트 사용 개념에만 연결하고 근거 문장을 함께 표시한다. 기록이 없을 때는 진단을 추측하지 않고 기록 부족을 명시한다.
- 새 개인정보를 수집하거나 저장하지 않고 기존 교사 담당 학급 RLS 범위의 학습 기록만 재구성한다.

# 2026-10-08 · 로딩 모션 기반 자연색 팔레트

- 로딩 모션에서 사용해 온 소나무색(`#245b43`), 흙빛 주황(`#d66a3f`), 잎사귀색(`#789321`), 청회색(`#667b8c`)을 서비스 전체의 공통 팔레트로 사용한다.
- 따뜻한 크림색은 페이지와 카드 바탕, 소나무색은 본문과 주요 동작, 흙빛 주황은 현재 위치와 주의 강조, 잎사귀색은 진행·완료 상태에 사용한다.
- 참고 사이트처럼 넓은 여백, 낮은 채도의 면, 얇은 경계선과 가벼운 그림자를 사용하고 강한 대각선 색면과 과도한 장식은 제거한다.
- 로그인, 학생 홈, 오늘의 챌린지, 스스로 유형학습, 오답노트, 교사 대시보드에 같은 상태 의미를 적용하며 학습 내용과 비계 순서는 바꾸지 않는다.
